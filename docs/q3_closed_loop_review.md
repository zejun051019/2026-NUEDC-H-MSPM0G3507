# 第三问闭环框架审查（2026-09-16）

## 验证状态

本次为框架修正，不是实机调参结论。ARM C 回归测试及固件构建通过；当前未检测到 XDS110 / COM12，未烧录新版本、未采集实机曲线、未确认五轮成功。
旧代码已有用户修改的 Kp=0.8、Ki=0、Kd=0.2，本次保留。8°连续输出上限是待验试验值，并非从几何表唯一推导出的最优值。

## 资料依据与验收

- 本地 `H题_车载平衡滚球运动控制系统.pdf` 第2页：第三问 O→+5→-5并稳定，时间≤5s、两点误差≤1cm。
- 第3页：左端固定、25cm PPR管、球约1cm、内壁要求光滑；严重局部坑洞不能保证仅靠调参解决。
- X42S手册5.3.14：X模式F1设置梯形位置参数，FC发送有符号0.1°目标；电机内部闭环。MCU没有再实现一套电机位置PID。
- 用户实测：电机正角使视觉坐标减小；约±7°动态脱困；25°是机械范围。端点高度表仅实测到18°，超过部分不能作为可靠辨识值。

## 修正的问题

1. 主循环delay后自增10ms漏计业务耗时。现在复用现有TIMG6硬件10ms时基，前台不停轮询新帧，不在ISR发电机命令。时间戳分辨率仍为10ms，不能宣称微秒实时或严格≤10ms最坏响应。
2. I参数曾因积分使能恒0而无效。现在积分分离，并在饱和同向/预判刹车时冻结积分。Ki默认仍为0。
3. 速度计算用相机16位源时间差，支持65536ms回绕，按实际dt低通。该位置仍是相机滤波后的测量，不能从rx_age推断曝光到执行总延迟。
4. 所有运动阶段使用最新位置检查±10cm边界、视觉和电机反馈新鲜度。置信度门槛50是初值；低置信度停止，未修改相机算法。
5. 目标改变保留速度，取消强制踢球。连续闭环确认卡住后才触发有次数/时间上限的±7°脱困；检测到0.2cm位移或已到目标带便提前结束脉冲。
6. 到达需要位置±1cm、速度≤0.5cm/s及稳定窗口；HOLD持续反馈，受扰后清除到达标志并恢复ACTIVE。
7. 第三问默认先闭环回中心，然后+5到达带立即折返，最终-5保持；取消正常结束的回零/软件复位。motion_started_ms计O到+5开始至-5稳定，不包含准备回中，正式比赛计时口径仍按现场规则核验。
8. PA31使用20ms稳定电平检测，一次完整按下只生成一次事件；第一次置当前零点，第二次要求收到置零后的新实际位置反馈。停止后可重新两次启动。
9. 无线日志改FIFO非阻塞发送、整行容量预检，增加逐控制帧C记录。旧文本的断行、积压不能当作控制延迟。
10. X42S返回解析按长度，不因位置数据内部的0x6B误结束（如10.7°）。当前只支持应用实际使用的X选项5字节、位置8字节及普通ACK4字节；不是任意厂家返回格式的通用解析器。

## 控制关系与局限

`视觉位置 → 按源时间估速 → 位置PID → 停车距离检查 → 电机角限幅/变化率限制 → FC → X42S内部闭环 → 实际角反馈监测`

外环输出单位是电机度。不是牛顿，也不是摆杆度。

`d_stop = |v| * T + v²/(2*a_brake) + margin`

`T = 基础延迟假设 + |所需制动角-电机实际角|/角速度上限`

仅向目标运动且剩余距离进入停车距离时，要求输出反向阻尼；每帧重算，低速解除，无固定反向保持时间。越过目标后PID的位置项和D项继续向减速方向作用。
初值a_brake=6cm/s²、基础T=0.15s、margin=0.2cm，需要实测。比例制动输出本身不保证恒定减速度，此模型用于触发提前减速，不承诺精确停车。

杆端4mm/250mm得到sin(theta)≈0.016；g*sin(theta)≈15.7cm/s²只是重力分量。理想实心球在平面纯滚动约乘5/7，槽内接触、摩擦和机构动态会改变有效加速度。因此不能仅据几何表保证8°在任意位置快速停住。

## 使用与优先阅读

1. `ball_control_config.h`：PID、制动模型、限幅、模式和目标。
2. `ball_position_control.c`：StartTargetCm、SetTargetCm、UpdateMeasurement、RunPID、Task。
3. `ball_brake.c`：速度方向、停车距离与制动释放。
4. `q3_sequence.c`：CENTER→TO+5→TO-5→HOLD-5。
5. `app_clock.c`、`vision_link.c`、`debug_log.c`：真实时钟、收帧、非阻塞日志。

单目标调试：`BALL_CONTROL_SINGLE_TARGET_MODE=1`，`BALL_CONTROL_SINGLE_TARGET_CM=目标厘米`，重新构建后两次PA31；目标允许[-9,+9]cm，起点须在(-10,+10)cm且视觉有效、机械零点有效。端部/已撞壁不属于本版已允许的自动恢复区域。
应用程序可调用`BallPositionControl_StartTargetCm(target, now)`启动，运行时`BallPositionControl_SetTargetCm(target, now)`换目标。由独占控制的应用状态机调用，禁止与Q3任务同时抢写目标。无线串口目前仅日志，未新增在线调参命令。

## 日志与验收

C记录字段依次为：t_ms,update,state,seq,target10,pos10,vel10,cmd10,act10,p10,i10,d10,stop10,brake,dt_ms,dispatch_age_ms,act_age_ms,fault。
位置/速度/角度/距离除以10还原。dt是相机源时间差，dispatch_age是接收后软件处理年龄，二者均不是端到端总延迟。
BC补充calc/tx/dt/lag/brake/stop10；Q3的finish_ms/timepass仅评价时间，不能代替完整成功判定。

硬件门禁：先确认时间流速和视觉连续性，再确认cmd/act跟踪及电机响应。之后固定模型参数做单目标正负各轮，依次辨识T和a_brake、调P/D、最后决定是否加I。每次只改一组参数，记录超调、稳定时间、饱和占比、跟踪误差、丢帧与故障。五轮Q3无碰挡、≤5s且-5±1cm持续保持才验收。
任意高速初始状态可能已没有足够停车距离；任何算法都不能保证“杆上任意位置任意速度必然救回”。
